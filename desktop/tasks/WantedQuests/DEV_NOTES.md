## 二、实现

| 文件 | 作用 |
| --- | --- |
| `tasks/WantedQuests/ui_wq_v2.py` | 新 UI 适配层（`WantedQuestsUiV2` 混入）：面板/详情识别、三卡读取、推荐行读取、「前往」坐标点击、`wq2_map_type` |
| `tasks/WantedQuests/script_task.py` | `run()` 开头探测新面板 → 走 `run_v2()`；`_click_goto_any()` 让 `secret/challenge` 同时接受 RuleImage 与坐标；`run_v2()` 主循环 |
| `tasks/WantedQuests/explore.py` | `explore()` 的「前往」也支持坐标入参 |
| `dev_tools/wq_ui_probe.py` | 不能看图时的读屏/点文本/模板打分/裁剪工具 |
| `dev_tools/wq_v2_probe.py` | 适配层只读验证：面板 → 卡片 → 详情 → 推荐行（`--click` 可点一次前往） |
| `dev_tools/wq_v2_check.py` | 纯逻辑单测 20 项（类型映射 / 进度归一化 / 数量解析 / goto 分发） |

**判定要点**
- 面板 vs 详情：详情弹窗也有「悬赏封印」标题，必须用「悬赏目标」排除，否则会在详情里当面板用。
- 进度归一化：OCR 常把 `0/3` 读成 `10/3天` → 当前数大于总数时取个位。
- 类型映射：新 UI 有「妖气」，OAS 内部按「探索」处理；`式神碎`→式神、`探索会`→探索（前缀匹配）。
- 「前往」用 `detect_and_ocr` 的文本块定位，**坐标要加回 ROI 原点**（detect 返回的是 ROI 相对坐标）。

## 四、已知限制（下一步）

1. **妖气（探索）行未接线**：新 UI 的「妖气」入口与旧 `WQExplore.explore` 的入口不同，
   目前遇到妖气行只记录并跳过（秘闻优先），需要单独实测妖气封印列表页再补。
2. **协作任务/邀请好友流程未适配**：`I_WQ_INVITE_*`、`I_WQ_FRIEND_*` 模板在新 UI 全部失效
   （`I_WQ_FRIEND_1..5` 的 PNG 甚至在仓库里不存在），`cooperation_only` 模式不可用。
3. 面板标题 OCR 偶发读出乱码（`[43498]`），已加「重拍一次 + 用下次刷新兜底」；
   若后续版本再改版，用 `dev_tools/wq_ui_probe.py shot` 重新取坐标即可。

## 五、协作邀请（2026-10-28 实测流程）

**弹窗结构（点击面板左侧「邀请好友」(246,416) 后）**
```
页签：好友(171,98) | 跨区(285,98)
标题：「邀请7级以上好友」(503,106)   「推荐阴阳师」(787,106)
提示：「对方同意后自动发送协作邀请」(772,144)
左列好友名单（x≈230~300，y≈190/290/390/490 每行约 96px）
中列另一组名单（x≈520~600）      右列推荐阴阳师（x≈850~950，带「不期而遇」关系标签）
底部：取消(266,560) | 邀请(536,557)
```

**实测交互（关键事实）**
1. 点好友名字后**界面文字不变**（选中只靠高亮，OCR 无法确认）；
2. 点「邀请」→ **弹窗直接关闭**，没有确认弹窗、没有 toast → 这就是「已发送」的唯一可观测信号；
3. 邀请成功后面板右下会出现「取消（取消邀请）」，同时协作卡仍是 `0/11`、`0/6`
   （要等好友同意并完成才涨）；
4. 名单在每次邀请后会重排，所以每次都要重新 OCR 取名字，不能缓存坐标。

**实现**：`ui_wq_v2.py` 的 `wq2_invite_friends(count, preferred)`
—— 每位好友单独开一次弹窗：开弹窗 → 选人 → 点邀请 → 弹窗关闭才算成功；
好友名用 `wq2_is_friend_name()` 过滤（排除 `55` 这类等级数字、页签与按钮文本）。
`run_v2()` 每轮开始调一次（`invited_once` 保护），配置 `cooperation_only=True` 时邀请完即结束。

**实机证据（17:14）**
```
[WQ] invite friend: 樱见 at (566,305) → [WQ] invite sent -> 樱见
[WQ] invite 5/5 -> 觅千
[WQ] cooperation invite sent: 5
面板复查：出现「取消」按钮（邀请中），协作卡 0/11、0/6 未变（等好友同意）
```

**未做**：跨区邀请（`跨区` 页签）、按 `cooperation_type` 挑协作任务类型、
`invite_friend_name` 指定好友失败后的退避（目前失败即取消并结束本轮）。

## 六、2026-11-01：任务卡变四张 + 面板兜底 + 前往探索

**游戏又调了面板布局**（实测今天 08:11 的帧）：
- 任务卡从 **3 张变 4 张**：任务文本 y≈456-459，x 起 **155 / 429 / 699 / 988**；
  进度「a/b」y≈481-483，x 起 **199 / 482 / 763 / 1040**（旧代码只认三张，会错位）。
- 面板右下角初始只有「**追踪**」(≈1137,635)；点过追踪后才出现「**前往探索**」(≈1067,691)。
  也就是说「前往探索」不是常驻按钮，先追踪再点。

**改动**
| 位置 | 内容 |
| --- | --- |
| `ui_wq_v2.py` 卡片常量 | 四张卡的文本/进度 ROI 与点击中心（x 155/429/699/988） |
| `ui_wq_v2.py` 进度识别 | 单卡微 ROI 误差大 → 改为**整条横带一次 Full OCR**，再按 x 就近分配给四张卡（实测 tokens: 217/500/782/1065 全部命中） |
| `ui_wq_v2.py` 面板判定 | OCR 失败时用模板兜底 `_wq2_panel_by_templates()`（追踪按钮存在 且 无详情/邀请弹窗） |
| `ui_wq_v2.py` 新增 | `wq2_goto_exploration()` + `_find_exploration_button()`：OCR 找「前往探索」→ 点击 → 校验 `I_CHECK_EXPLORATION` |
| `module/device/device.py` | 截图异常捕获补 `NemuIpcError`（模拟器重启时会抛，之前会穿透任务） |
| `dev_tools/screenshot_fallback_check.py` | 前台判定打桩，回归不再依赖「游戏是否在前台」 |
| `dev_tools/wq_v2_live_test.py` | 新增实机验证脚本（10 项） |
