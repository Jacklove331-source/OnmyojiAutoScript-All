## 四、评分等价性（最终口径，2026-11-20 08:18 复跑）

### 4.1 平安志评分语义（从它自己的 `detail_json` 反推并验证）

1. **评分资格只过滤 4 项**：`quality` ∩ `slots` ∩ `setIds` ∩ `slotMainPairs`。
   * 不看 `level`、不看 `initialSubstatCounts`（+15、3 腿的御魂照样命中「四腿」规则）；
   * 不看 `requiredSubstats.allOf / anyOf`；
   * 不看 `forbiddenSubstats`。
2. **分数**：`score = Σ_core 10×(1+手数) + Σ_general 5×(1+手数)`；与数值无关；固有属性按 0 手计入，可与同名副属性**重复计分**。
3. **选规则**：有资格的规则里取最高分；同分取数组序靠前。
4. 没有规则有资格 → 分数 0，界面显示占位标签「未匹配评分规则卡片」。

「胚子准入」是**另一条路径**（28 条规则全项判定，含等级/腿数/allOf/anyOf），只影响分类与待办，不影响 `standardScore`。两条路径已分别实现、分别验收。

### 4.2 三条独立 oracle 的一致率

| Oracle | 样本 | 配对质量 | 分数一致 | 规则/判定一致 |
|---|---|---|---|---|
| A. 平安志界面抓表 `scores_all.json` | 3517 行 | 唯一 3517 / 多候选 0 / 未配对 0 | **3517/3517 = 100.00%** | 3432/3517 = 97.58%* |
| B. 平安志自身 sqlite `analysis_todo.detail_json` | 3547 行 | 唯一 3547 / 重复 0 / 未配对 0 | **3547/3547 = 100.00%** | **3547/3547 = 100.00%** |
| C. 胚子准入 `admission.rules[]` | 99,316 对 | 逐对判定 | — | **99316/99316 = 100.00%** |

\* A 的 85 条标签差异**全部**是「界面=未匹配评分规则卡片 vs 本引擎=None」，双方分数同为 0；「双方都有规则名但标签不同」= 0 条，「一方有规则另一方没有」= 0 条。因此语义上规则一致也是 **3517/3517 = 100%**。

B 的额外交叉校验：`analysis_todo.standard_score` 列 == `detail_json.standardScore.score` == 本引擎，三者在 3547 条上**逐条相等**（3547/3547）。早期文档里「DB 分数只有 77.6%」的说法是错误比较器产出的，已作废（见第 9 节）。
