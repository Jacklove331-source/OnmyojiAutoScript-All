# 账号资产 / 御魂 / 式神 自读：字段契约（对齐平安志的做法）

目标：**OAS 自己读，卸载平安志也照常工作**。读取方式与平安志一致——注入游戏进程，借它自己的
CPython 跑我们的读取脚本，产出与下面一致的 JSON，再由现有 ingest 落库。

本文件定义"必须产出什么"，不规定"怎么读出来"。验收只看字段与数值对不对。

## 1. 快照（一次读取 = 一份快照）

```json
{
  "profile": {"id": "<角色ID>", "name": "<角色名>", "server": "<服务器>",
               "captured_at": "2026-11-21T20:00:00Z"},
  "souls":  [ ... ],      // 见 §2
  "owned":  [ ... ],      // 见 §3
  "extras": {"currencies": { ... }, "realm_cards": {...}}   // 见 §4
}
```

字段名与 `tasks/Workbench/ingest/paz_db.py`（souls/owned/profile）和
`tasks/Workbench/ingest/paz_extra.py`（currencies/realm_cards）现有解析完全一致——
只要产出这份 JSON，下游 `/workbench/*`、评分、面板、OASX 页面全部零改动可用。

## 2. souls[]（御魂）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `internal_id` | str | 御魂实例唯一 id（同账号内稳定） |
| `set` | str | 套装 id（如 `针女`/`破势`） |
| `slot` | int | 号位 1..6 |
| `quality` | int | 星级（4/5/6） |
| `level` | int | 强化等级 0..15 |
| `main` | str | 主属性类型 |
| `main_value` | float | 主属性数值 |
| `attributes` | list[[str, float, int]] | `[属性, 数值, 强化手数]` |

实测基线：3,226 条（平安志 2026-11-21 16:45 快照）。

## 3. owned[]（式神）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | str | 图鉴/式神 id |
| `instance_id` | str | 实例 id |
| `star` | int | 星级 |
| `level` | int | 等级 |
| `awakened` | bool | 是否觉醒 |
| `skin` | int/null | 皮肤 |

实测基线：1,423 条。

## 5. 验收

1. `python tasks/Workbench/selftest_paz.py` 与 `selftest_features.py` 全绿（它们吃同一份 schema）。
2. 同一时点自读结果与平安志快照逐项比对：`souls` 条数、前 20 条 `(set, slot, quality, level, main_value)` 全等；
   `currencies` 12 项全等（允许游戏内自然增减，改比对时点）。
3. OASX「账号资产」卡显示 `来源：本机读取`、`读取于 <时间>`。

## 6. 已知门槛（按顺序解决）

1. **注入器**：`ptrace` attach → `dlopen` 我们的 `.so`。平安志用的是这条路且能在本作存活；
   `frida` 那条已实测会被杀（见 `references/paz-injector-reuse-attempt.md`）。
2. **进程内取 CPython**：`libclient.so`（141 MB）**不导出** `Py*` 符号，必须按 `/proc/self/maps` +
   `/proc/<pid>/mem` 解析偏移，或 `dladdr` + 扫描 `.dynsym`。这是主要技术难点。
3. **数据结构**：拿到解释器后枚举 `sys.modules` / 游戏全局对象，定位背包与货币。未知项最多的一步。
4. **反外挂容忍度**：先在不重要的角色上验证（不能拿托管账号试）。
