## 已实现的改进

| 方面 | 新行为 |
|---|---|
| 恢复验证 | 新截图识别失败不会回用旧页面缓存；至少连续两次识别稳定；检查预期页面。 |
| 战斗动画与等待 | 仅等待、仍停在原页面时不会宣布恢复或写入成功知识。任务可以通过 `verify_task_progress` 明确证明同页业务进度。 |
| 失效方案 | 重新截图、带上失败原因重新分析；默认最多一次重规划，仍受单次调用和动作总数限制。 |
| 慢响应 | 执行动作前再次核对页面与截图，画面明显变化时放弃旧方案，重新分析。 |
| 坐标 | 局部截图中的点击点与模板区域换算回全屏；OCR 调整后按实际落点重新检查禁点区；拒绝 NaN / Infinity。 |
| 知识库 | 按账号隔离；复用失败后用新截图分析；保存实际执行坐标和恢复目标；旧的弱验证记录保留但不自动复用。 |
| 模板 | 只有恢复验证通过的单按钮方案才可成为自动点击模板；按账号、任务、分辨率、版本、来源页面筛选。 |
| 模板质量 | 拒绝纯色图块，整张负样本检查混淆，相同按钮多处出现时不任选其一；过期或连续两次失效的模板停止自动点击。 |
| 设备互斥 | 同一设备通过进程间接管锁避免两个自愈器同时操作；锁随上下文退出释放。 |
| 冷却与重启 | 冷却、尝试次数持久化；默认一小时窗口，避免重启清空次数，也避免进程存活期间永久封死同一异常。 |
| 费用与次数 | 请求发出前持久化预留；失败请求和 HTTP 重试也计数；成功结算不重复增加调用次数。预算文件损坏时停止调用。 |
| 检测接入 | 修复点击事件未进入监控器的问题；配置定期刷新；已知页面优先包含当前任务。 |
| 失败升级 | 每次接管有最终结果；无法恢复的事故归并为持久化修复请求，后来验证成功后自动关闭对应请求。 |
| 运维 | 新增本地 `health` 与 `repairs` 命令，可查看结果统计、预算、旧记录、模板与待修复事项。 |

## 使用与检查

在 OAS 根目录运行：

```powershell
.\toolkit\python.exe -X utf8 -B -m module.ai_recovery.selftest
.\toolkit\python.exe -X utf8 -B -m module.ai_recovery.hardening_test
.\toolkit\python.exe -X utf8 -B dev_tools\ai_recovery_cli.py health oas3
.\toolkit\python.exe -X utf8 -B dev_tools\ai_recovery_cli.py repairs oas3
```

已有运行中的任务进程需要在正常停止后重新启动，才能加载升级后的 Python 模块。
无需调整游戏账号配置或重新填密钥。

可选的新配置项（不填也生效）：

```yaml
budget:
  reservation_cny: 0.03
detector:
  incident_window_s: 3600
safety:
  verification_frames: 2
  replan_attempts: 1
  plan_stale_change_ratio: 0.18
templates:
  max_age_days: 14
  min_match_margin: 0.04
```

费用预留为保守估计：无完整 usage 的失败请求保留预留费用，不能把它当成供应商账单。
配置中的原有日调用、小时调用和日费用上限继续生效。一次接管默认最多两次分析，
HTTP 重试也占用该额度。

## 验证范围与后续接口

本次使用 76 项自检、31 项新增回归、8 个定向缺口回放和 6 份历史事故记录验证。
尚未完成真实模型端到端调用和真实游戏任务验收。历史回放验证的是恢复判定，
不代表已经把当日地域鬼王队伍、难度选择或战斗业务流程修好。

新皮肤、全新布局或任务流程大改会留下修复请求。队列目前负责提供证据和去重，
不自行启动另一个编码代理、改写业务代码或发布适配补丁。后续可以对接 Codex
修复工作器，按「隔离补丁—历史回放—实机验证—应用/回滚」处理这些任务。

对于同一页面内的业务进度，任务适配器可以实现：

```python
def verify_task_progress(self, anomaly, diagnosis):
    # 只根据已确认的回合、计数或任务状态推进返回 True。
    return False
```

目前通用适配器不会凭动画变化猜测业务进度。恢复回到大厅后，原任务的状态机若
不能从大厅继续，仍需要该任务自身的重入/重试适配。
